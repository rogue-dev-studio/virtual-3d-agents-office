# Virtual 3D Agent Office

An explorable, **two-floor 3D technology office** in the browser where nine AI agents are
represented as animated characters: they sit at their workstations, walk between rooms and
floors, take breaks, and report what they are working on through an in-world HUD.

> **This is a front-end simulation.** Agent activity is generated by a seeded scheduler
> (`mulberry32`). No language model, backend or network call is involved. The UI says
> *Simulation* wherever activity is shown, and it is never presented as real AI work.

**Author:** [Rogue Development](https://github.com/rogue-dev-studio) (`@rogue-dev-studio`) ·
**Product:** AI Agents Rogue v1.4.0 · **License:** MIT (see `LICENSE`, `NOTICE`)

## Quick start

```bash
npm install
npm run dev        # http://localhost:5173
```

Production build + local preview:

```bash
npm run build      # -> dist/
npm run preview    # http://localhost:4173
```

Tests:

```bash
npm test           # unit tests (Vitest)
npm run e2e        # browser end-to-end (Playwright; starts `npm run preview` itself)
```

Requires Node 20+ (developed on Node 26). Playwright browsers: `npx playwright install chromium`.

> **Headless note:** WebGL falls back to SwiftShader in headless Chromium (≈1 fps) which is too
> slow for the e2e suite. `playwright.config.js` therefore launches Chromium with
> `--use-gl=angle --use-angle=d3d11 --enable-gpu` so the real GPU is used (≈24–31 fps here).

## What is in the office

- Two floors: **L1** (reception, open-plan workspace, CEO office, meeting rooms, QA lab, server
  room, pantry, lift/stairs) and **L2** (divisions, studio, training room, billiard/lounge,
  reading corner, game area, terrace). 36 rooms, 227 fixtures, 131 activity slots.
- **Nine agents** across five divisions, each with a home workstation (chair), role, division,
  live status, current task, task room, progress and event log.
- Simulated day: idle → thinking → working → (meeting / break / floor change) → completed, with
  seat reservation (a chair holds one occupant), A\* pathfinding, door animation and level
  travel via the stairs/lift.
- **Credits & Asset Licenses** modal: every third-party asset with author, source URL, license
  and status, fed from one central registry (`src/data/assetCredits.js`).

## Architecture

Data-driven and layered: **world data → scene builders → agents/simulation → interaction → UI**.
Rendering never owns domain logic and the dataset is never mutated.

```
index.html
src/
  main.js              composition root: boot, wiring, animation loop
  core/                renderer, GLTF/HDRI asset cache, loading screen, quality presets, events
  world/               worldData (load+validate), coords, materials, building (+doors),
                       furniture (vendored GLB), props (CC0 tech props), signage
  agents/              agent (model+mixer+state), animations (clip mapping), navigation
                       (raster + A* + seat clearance), simulation (seeded scheduler), labels
  interaction/         camera rig (orbit/focus/follow/floors), picking (raycast + Box3 proxies),
                       input (pointer/keyboard)
  ui/                  hud, detail panel, overlays (credits/help), fallback, dom helpers
  data/                agents, divisions, status, rooms, fixtures, officeAdditions, assetCredits
  styles/main.css      HUD + panel styling
tests/unit             Vitest: layout invariants, simulation determinism/clash-freedom
tests/e2e              Playwright: boot/render, movement, panels, missing-asset, screenshots
```

Key decisions are recorded in `docs/architecture/decisions.md` (ADR-1 … ADR-7). The single
coordinate conversion lives in `src/world/coords.js` (`toThree(x, y, height) = (x, height, -y)`).

## Quality presets

`Auto · Low · Medium · High` (persisted in `localStorage`, overriding via `?quality=low|medium|high`).
A preset controls shadow map, pixel ratio, image-based-lighting intensity and how many desk props
are placed. `?quality=` and `?seed=` are also handy for reproducible tests.

## Limitations (v1, honest list)

- **Front-end simulation only** — no backend, auth, persistence or real agents.
- **Not 60 fps at Medium on this machine.** Measured on an integrated **AMD Radeon HD 8200 / R3**
  at 1920×1080: **Low ≈ 24 fps / 163 draw calls**; **Medium ≈ 18 fps / 351 calls / 2.4 M tris**;
  **High ≈ 5 fps**. The scene is geometry- and shadow-bound on weak iGPUs. See
  `docs/qa/QA-REPORT.md` for the recommendation (prop LOD / shadow-caster trimming).
- The DOM fallback (no-WebGL) path is implemented but **not covered by an automated test**.
- Small (< ~2 m²) pockets behind upstream furniture in four rooms are unreachable by agents
  (98.8 % / 96.0 % of each floor is reachable); seats and doorways are carved and remain reachable.
- English UI copy; the vendored dataset keeps its own room ids internally.
- Not deployed anywhere — deployment needs explicit approval.
